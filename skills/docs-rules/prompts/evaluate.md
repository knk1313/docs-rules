# 文書をAIで評価する手順

書き終えた文書を、決まった観点で評価し、違反を箇所つきで返すための手順。評価だけを行い、文書は直さない。結果の形と観点の一覧は[README.md](README.md)を参照。

## 評価する主体

- サブエージェントを使える環境では、このファイルと評価する文書のパスをサブエージェントに渡し、評価させる。書いた本人とは別のコンテキストで読むと、自分の文書を甘く評価するのを避けられる
- サブエージェントを使えない環境では、書き終えた文書をファイルに保存し、ファイルを読み直してから評価する。書いている途中の記憶ではなく、保存した文書だけを根拠にする

## 読むもの

次の順に読む。

1. [rules/README.md](../rules/README.md)の「ファイルの分け方」の表にあるファイルを、すべて読む
2. 文書種別が決まっているときは、`schemas/<識別名>.md`の「セクションごとの書き方」を読む
3. 評価する文書

## 評価の対象

- `判定：AI`のルール：すべてを対象にする
- `判定：機械`のルール：ルールの下の注記に「AI評価で扱う」とあるものだけを対象にし、注記に書かれた部分だけを評価する（GRM-001の文末の混在、GRM-002の論点の数など）。それ以外の`判定：機械`のルールは評価しない。`evaluators/score.mjs`が採点するため、重ねて指摘しない
- `schemas/<識別名>.md`の各セクション：「書くこと」「書かないこと」「粒度の目安」に照らして、セクションの中身を評価する。見出しの有無と順序は評価しない
- 文書種別が決まっていないときは、`schemas/`の評価を飛ばし、`skipped_rules`に`{"rule_id": "schemas", "reason": "文書種別が決まっていない"}`を入れる
- 評価の対象に入らない`判定：機械`のルールは、`checked_rules`と`skipped_rules`のどちらにも入れない

## 評価のしかた

1. 観点を一つずつ取り上げ、文書の全体を読んで当てはまる箇所を探す。複数の観点をまとめて判断しない
2. 各ルールの「ルール」と「例」を合否の基準にする。例の失敗例に近い書き方があれば違反とする
3. 違反は箇所ごとに1件とする。同じ観点の違反が文書の中に3か所あれば3件にする
4. 根拠を示せない違反は出さない。「もっと具体的にできる」のような、直す先を名指しできない指摘は違反にしない
5. 文書に当てはまらない観点は合格とする

## 違反の書き方

- `rule_id`：ルールIDか、`<識別名>#<見出し名>`（例：`proposal#背景と課題`）
- `excerpt`：違反の箇所を、文書から一字も変えずに写す。要約や言い換えをしない。書き直しのときに、この文字列で箇所を探す
- `line`：`excerpt`の先頭がある行の番号（1始まり）。数え間違えることがあるため、目安として書く
- `column`：`null`
- `fix`：どの語をどう直すか、または何を足すかを書く。粒度の目安の違反では、足りない要素を名指しする（例：「期日を日付で足す」「費用を金額で書く」）。「具体的にする」「分かりやすくする」のような一般論は書かない
- `judge`：`AI`
- `checker`：`prompts/evaluate.md`

## 出力

次の形のJSONだけを出力する。前後に説明の文を付けない。

```json
{
  "file": "<評価した文書のパス>",
  "checked_rules": ["CMP-001", "FW-003", "GRM-002", "proposal#決めてほしいこと"],
  "skipped_rules": [],
  "violations": [
    {
      "rule_id": "proposal#背景と課題",
      "line": 8,
      "column": null,
      "excerpt": "現在、いくつかの課題がある。",
      "fix": "先方が確かめられる事実（件数、期間、金額）を一つ以上足す。例：「問い合わせが月に約120件ある」",
      "judge": "AI",
      "checker": "prompts/evaluate.md"
    }
  ]
}
```

- `checked_rules`には、評価した観点の`rule_id`をすべて入れる
- `skipped_rules`の各項目は、`rule_id`と`reason`を持つオブジェクトにする。文字列だけを並べない
- 違反がないときは、`violations`を空の配列にする
