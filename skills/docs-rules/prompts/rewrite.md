# 違反を渡して文書を書き直す手順

採点（`evaluators/score.mjs`）と評価（[evaluate.md](evaluate.md)）で見つかった違反を、文書の該当箇所だけで直すための手順。繰り返しの回数と止める条件は`SKILL.md`の「4. 点検してから出す」に書く。このファイルには、1回の書き直しで何をどこまで変えるかだけを書く。

## 受け取るもの

- 書き直す文書（保存したファイル）
- 直す違反の一覧。採点結果と評価結果の`violations`のうち、`SKILL.md`の手順で書き直しの対象にしたもの

## 箇所の探し方

1. `excerpt`の文字列を、文書の中から探す。`line`は目安として使い、`excerpt`が見つかった位置を正とする
2. 同じ`excerpt`が文書に複数あるときは、`line`と`column`に最も近い箇所を選ぶ。同じルールIDで同じ`excerpt`の違反が複数渡されたときは、見つかった箇所を1件ずつ割り当てる
3. `excerpt`が文書の中に見つからない違反は直さず、「直せなかった違反」に入れる。理由は「excerptが文書にない」とする

## 直し方

- `fix`が`「A」→「B」`の形なら、その箇所のAをBに置き換える。置き換えると文がつながらないときは、同じ文の中で語順や助詞を直してよい
- `fix`の置き換え先が`rule_id`のルールと食い違うときは、ルールに従う。採点の`fix`はツールの修正候補をそのまま写しており、docs-rulesの基準と違うことがある
- `fix`がそれ以外の形なら、`rule_id`のルール（`rules/`か`schemas/<識別名>.md`）の「ルール」と「例」に沿って直す
- 直すのは、`excerpt`を含む文だけとする。文を分ける、つなぐ、箇条書にするといった直し方が要るときも、その違反のある段落の中で行う
- 文書にも利用者の依頼にもない事実（件数、期日、金額、担当者の名前など）を作って足さない。`fix`がそうした事実を足すよう求めているときは直さず、「直せなかった違反」に入れる。理由は「文書と依頼に情報がない」とする
- 1つの違反を直すために、ほかのルールの違反を新しく作らない。`rules/`の表記と文体はそのまま守る

## 変えないもの

- `#`の標題と`##`の見出しの文言、`##`の見出しの順序。違反の`excerpt`が標題を指すときだけ、標題を直してよい
- `###`以下の見出し。違反の`excerpt`がその見出しを指すときだけ直してよい
- 渡された違反のない文。言い回しを整える、情報を足す、順序を入れ替えるといった、違反と関係のない変更をしない
- コードブロックの中身、表の列の構成、リンク先のURL

## 出力

1. 書き直した文書を、前の版とは別のファイルに保存する。前の版は、`SKILL.md`の手順で書き直しを取り消すときに使うため、上書きしない
2. 直せなかった違反を、次の形のJSONで返す。すべて直せたときは`unfixed`を空の配列にする

```json
{
  "unfixed": [
    {
      "rule_id": "proposal#背景と課題",
      "excerpt": "現在、いくつかの課題がある。",
      "reason": "文書と依頼に情報がない"
    }
  ]
}
```
