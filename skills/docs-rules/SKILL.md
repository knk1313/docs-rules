# docs-rules

日本語の文書を、共通のルールに沿って書き、機械の検査で確かめるためのスキル。ルールの本体は`rules/`に置き、このファイルには読む順と点検の手順だけを書く。

## 1. ルールを読む

`rules/`の次のファイルを読む。ルールはすべて、`evaluators/score.mjs`で機械的に検査できる。

| ファイル | 内容 | 例 |
| --- | --- | --- |
| `rules/notation.md` | スペース、英数字、記号 | 全角と半角の間にスペースを入れない、「！」「？」を使わない |
| `rules/grammar.md` | 文末、接続、否定、語の形 | 常体と敬体を混ぜない、ら抜き言葉を使わない |
| `rules/forbidden-words.md` | 冗長な言い回し | 「〜することができる」「〜を行う」を使わず「〜できる」「〜する」で書く |
| `rules/markup.md` | Markdown記法 | 見出しの階層を1段ずつ下げる、箇条書の記号は「-」 |

## 2. 書く

読んだルールに沿って書く。文書はファイルに保存する。

## 3. 検査して直す

1. `node <スキルのディレクトリ>/evaluators/score.mjs <文書のパス>`を実行する。`<スキルのディレクトリ>`は、このSKILL.mdがあるディレクトリの絶対パスである。Claude Codeでは、スキルを読み込んだときに「Base directory for this skill」として示される
2. 出力のJSONの`violations`を直す。各違反の`rule_id`、`line`、`excerpt`で箇所を探し、`fix`に沿って直す。`rule_id`が`null`の違反は、ツールのメッセージ（`fix`）に従う
3. 直した後、もう一度検査する。違反がなくなるか、同じ違反が2回続けて残るまで繰り返す。繰り返しは3回までにする

- 終了コードは、0が違反なし、1が違反あり、2が引数の誤り、3がツールを実行できなかったことを示す。2なら引数を直す
- `node`がない、または終了コードが3の場合は、検査を飛ばし、そのことを報告に書く。ルールを読み直して目で確かめる
- 詳しい使い方は`evaluators/README.md`を参照

## 4. 報告する

検査の結果を、文書とは別の返答で利用者に示す。

```text
検査の結果：直した違反5件（NOT-022、FW-001ほか）、残った違反1件
- 残った違反：GRM-005「担当者に今日中に」（2回続けて残った）
```

- 最初から違反がなかったときは、「検査の結果：違反なし」の1行にする
- 検査を飛ばしたときは、1行目にそのことを書き添える

## 5. 改善点の候補を残す

ルールや検査の不備に気付いたら、改善点の候補として報告に足す。候補がなければ何も書かない。候補にする場面は次の三つ。

- 誤検出：検査が、ルールに照らして違反でない箇所を指摘した
- 直せない違反：同じ違反が2回続けて残った
- 手で直した箇所：出力の後に利用者が直した箇所のうち、ルールが足りないために起きたもの

```text
改善点の候補：GRM-005（誤検出）「表示が崩れる不具合が見つかった」の二つの「が」を指摘したが、別々の述語に掛かる
```

報告に書いた後、`<スキルのディレクトリ>/../docs-rules-feedback/scripts/feedback.mjs`があれば、候補を1件ずつ保存する。

- コマンド：`node <そのパス> add '<JSON>'`。JSONに「'」が入るときは、引数ではなく標準入力で渡す
- JSONの項目：`rule_id`、`scene`（場面の名前）、`reason`、`excerpt`（該当箇所。20字まで）
- ファイルがない場合（claude.aiなど）は保存しない。保存した候補は、`docs-rules-feedback`スキルでIssueにできる
