# docs-rules

日本語の文書を、共通ルールと文書種別ごとの構成に沿って書くためのスキル。ルールの本体はこのファイルには書かず、下位ディレクトリに置く。このファイルには、どのファイルをどの順に読み、どう点検するかだけを書く。

## 1. 文書種別を決める

扱う文書種別は次の2つ。

| 種別 | 識別名 | 例 |
| --- | --- | --- |
| セッションログ | `session-log` | 作業セッションの経緯・決定事項・残課題のまとめ |
| 提案書 | `proposal` | 課題・提案内容・期待される効果を示す文書 |

- 利用者が種別を言った場合：その種別を使う
- 利用者が種別を言わない場合：確認を挟まず、依頼内容から推定した種別で書く
- どちらの種別にも当てはまらない場合：種別を決めず、共通ルール（`rules/`）だけを適用する

## 2. 参照するファイルを読む

次の順に読む。後に読むものほど、その種別に固有の内容になる。

1. `rules/`：全種別に共通する表記・文体・Markdown記法のルール。先に`rules/README.md`を読んでルールの型と出典の略称を把握し、次に残りのファイルを読む
2. `schemas/<識別名>.md`：その種別の必須セクションと文書構造（例：`schemas/session-log.md`）
3. `templates/<識別名>.md`：その種別の見出しの型（例：`templates/proposal.md`）

- ファイルやディレクトリが存在しない場合は飛ばし、存在するものだけに従う
- 種別を決めなかった場合は、1だけを読む
- 共通ルールと種別ごとの定義が食い違う場合は、種別ごとの定義を優先する

## 3. 書く

- 2で読んだテンプレートの見出しの型に沿って書く。テンプレートがない場合は、スキーマの必須セクションを見出しにする
- テンプレートの案内のコメント（`<!-- -->`）は出力に残さない
- 必須セクションは省かない。書く内容がないセクションは、その旨を一文で書く

## 4. 点検してから出す

書き終えたら、出力する前に次の手順で自己点検する。

1. 書いた文書をファイルに保存し、`node evaluators/score.mjs <文書のパス> --type <識別名>`（このスキルのディレクトリからの相対パス）を実行する。種別を決めなかった場合は`--type`を付けない。終了コードが1なら、出力のJSONの`violations`を直す。`node`がない、または終了コードが3の場合は、機械判定を飛ばしたことを利用者に伝え、次の手順だけで点検する。使い方の詳細は`evaluators/README.md`を参照
2. `prompts/evaluate.md`の手順で、文書をAIで評価する。サブエージェントを使える環境では、評価をサブエージェントに渡す。出力のJSONの`violations`を直す。`prompts/`がない場合は、2で読んだ`rules/`と`schemas/`に照らして違反を探す
3. 見つけた違反を直してから出力する

参照先が1つも存在しない場合は、点検を省いてよい。

> この節は暫定の手順。採点と評価の結果を渡して書き直す繰り返し（#24）を足した時点で差し替える。
