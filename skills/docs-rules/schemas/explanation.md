# 解説（explanation）

書き方の型は[README.md](README.md)を参照。

## 目的と読み手

- 目的：読み手が、なぜそうなっているかを理解できるように、背景、考え方、ほかの案との違いを示す。設計の背景、方針の説明、概念の説明がこの種別に当たる
- 読み手：作業の手を止めて、対象の全体を理解したい人。対象を使ったことはあるが、理由や経緯は知らない前提で書く
- 対象外：ADR（設計の決定の記録）。ADRは何を決めたかの記録で、なぜそうなのかを示す解説とは目的が違う。決めたことの記録はセッションログで書く。作業の手順（ハウツー）と、事実の一覧（リファレンス）もこの種別では書かない
- 位置づけ：Diátaxisの解説（理解×学習）に当たる（[README.md](README.md)の「文書種別の決め方」）
- 境目：リファレンスは事実だけを書き、理由、経緯、意見は解説に回す。解説は理解のための文書で、決定を求めない。読み手に決定を求める文書は、提案書にする

## 入力

- 設計の資料、方針を決めたときの議論の記録、関連する資料
- セッションログ（[session-log.md](session-log.md)）を入力にできる。対応は次の表のとおり

| セッションログのセクション | 解説で使うセクション |
| --- | --- |
| `## 概要`、`## 決めたこと` | `## 要旨` |
| `## 検討した経緯` | `## 背景`、`## ほかの選択肢との比較` |
| `## 決めた理由` | `## 考え方` |
| `## 参照` | `## 関連文書` |

- セッションログの日付ごとの経過や、担当者間のやり取りは写さない。今も成り立つ背景と理由だけを書く

## 必須セクション

解説には、次のセクションを表の順に置く。

| 順 | 見出し名 | 役割 |
| --- | --- | --- |
| 1 | `## 要旨` | 何について説明するかと、その要点を示す |
| 2 | `## 背景` | 経緯、制約、前提となる事情を示す |
| 3 | `## 考え方` | 設計の判断や方針と、その理由を示す |
| 4 | `## ほかの選択肢との比較` | ほかの考え方や案と比べ、選ばなかった理由を示す |
| 5 | `## 関連文書` | 手順やリファレンスの文書へのリンクを並べる |

## セクションごとの書き方

### 要旨

- 書くこと：何について説明するかと、文書全体の要点
- 書かないこと：背景の詳しい経緯、手順
- 粒度の目安：2〜4文。要旨だけを読んでも、要点が分かるように書く

### 背景

- 書くこと：対象が生まれた経緯、置かれている制約、前提となる事情
- 書かないこと：今は成り立たない古い事情、考え方の理由（「考え方」に書く）
- 粒度の目安：3〜6文。制約は、数値や期日など確かめられる事実で書く

### 考え方

- 書くこと：設計の判断や方針と、その理由。理由は、背景に書いた制約や事情と対応させる
- 書かないこと：手順、設定値の一覧（リファレンスの文書に回す）
- 粒度の目安：判断ごとに`###`か箇条書の項目を分け、1項目に判断と理由を書く。判断は2〜5個に絞る

### ほかの選択肢との比較

- 書くこと：ほかの考え方や案と、それを選ばなかった理由。比べる観点が二つ以上ある場合は表で示す
- 書かないこと：どの案を選ぶべきかの推奨（決定を求める場合は提案書にする）
- 粒度の目安：各案の説明は1〜2文。比べる案がない場合は「比べた案はない」と一文で書く

### 関連文書

- 書くこと：考え方に沿って作業する手順、設定値を引くリファレンス、関連する解説へのリンクと、何の文書かを示す短い説明
- 書かないこと：説明と関係しない文書
- 粒度の目安：1項目1行。関連する文書がない場合は「関連する文書はない」と一文で書く

## 文書全体の制約

- 見出しは[README.md](README.md)の「見出しの規約」に従う
- 文書名（`#`）は「〜について」と読める形にする。「〜の背景」「〜の考え方」のように、何を説明するかを入れる（Diátaxis、参照のみ）
- 手順と事実の一覧を混ぜない。要る場合は、ハウツーかリファレンスの文書へのリンクにする（Diátaxis、参照のみ）
- 意見や評価を書く場合は、誰の判断かと、その理由を添える（Diátaxis、参照のみ）
