# 提案書（proposal）

書き方の型は[README.md](README.md)を参照。

## 目的と読み手

- 目的：先方（顧客）に渡し、先方に意思決定してもらう。何を決めてほしいのか、決めるための材料、決めた後に何が起きるのかを示す
- 読み手：社外の先方。提案の内容を決める立場の人と、その判断を支える担当者。社内の事情や経緯を知らない前提で書く
- 対象外：社内の意思決定に使う提案。この種別では扱わない
- 位置づけ：Diátaxisの4分類の外。背景と理由の部分は解説に近いが、決定を求める構成はこのスキーマで独自に定める（[README.md](README.md)の「文書種別の決め方」）

## 入力

- 先方から聞いた現状と要望、見積もりや工程の資料
- セッションログ（[session-log.md](session-log.md)）を入力にできる。対応は次の表のとおり

| セッションログのセクション | 提案書で使うセクション |
| --- | --- |
| `## 概要`、`## 決めたこと` | `## 背景と課題` |
| `## 検討した経緯` | `## 選択肢と比較` |
| `## 決めた理由` | `## 推奨案と理由` |
| `## 未解決の課題` | `## 決めてほしいこと`（先方に決めてもらう事項の候補） |
| `## 次に引き継ぐこと` | `## 決定後に起きること` |
| `## 参照` | `## 参考資料`（先方が開ける資料だけ） |

- セッションログは社内向けの記録である。社内の事情（原価、担当者間のやり取り、社内の未決事項）は提案書に写さない

## 必須セクション

提案書には、次のセクションを表の順に置く。

| 順 | 見出し名 | 役割 |
| --- | --- | --- |
| 1 | `## 決めてほしいこと` | 誰に・いつまでに・何を決めてほしいかを問いの形で示す |
| 2 | `## 背景と課題` | 決める必要がある理由として、先方の現状と困りごとを示す |
| 3 | `## 選択肢と比較` | 2〜3案と、比較の観点ごとの違いを示す |
| 4 | `## 推奨案と理由` | どの案を推すかと、その理由を示す |
| 5 | `## 決定後に起きること` | 決定後の手順、スケジュール、影響範囲、先方に必要な費用や人員を示す |
| 6 | `## 参考資料` | 根拠にした資料を並べる |

## セクションごとの書き方

### 決めてほしいこと

- 書くこと：決めてほしい人（役職または名前）、期日、決めてほしい事項。事項は「〜を採用するか」「AとBのどちらにするか」のように問いの形で書く
- 書かないこと：背景の説明（「背景と課題」に書く）、推奨案の理由（「推奨案と理由」に書く）
- 粒度の目安：3文以内。期日は日付で書く。決めてほしい事項が二つ以上あるときは番号付きの箇条書にする

### 背景と課題

- 書くこと：先方の現状、困りごと、今決める必要がある理由
- 書かないこと：自社の社内事情、先方が確かめられない推測
- 粒度の目安：3〜6文。先方が確かめられる事実（件数、期間、金額）を一つ以上入れる

### 選択肢と比較

- 書くこと：2〜3案と、比較の観点（費用、期間、リスクの3点を基本とする）ごとの違い。比較は表で示す
- 書かないこと：どの案を推すか（「推奨案と理由」に書く）、検討の途中で外した案の詳細
- 粒度の目安：各案の説明は1〜2文。表の各欄は数値か短い語で書く

### 推奨案と理由

- 書くこと：推す案を一つと、その理由。理由は「選択肢と比較」の観点に沿って書く
- 書かないこと：「選択肢と比較」に出していない新しい案
- 粒度の目安：理由は2〜4項目の箇条書。各項目に比較の観点を一つ対応させる

### 決定後に起きること

- 書くこと：決定後の手順、スケジュール、影響を受ける範囲、先方に必要な費用・人員・作業
- 書かないこと：決定前にやる作業、社内の作業分担
- 粒度の目安：手順は番号付きの箇条書で、各手順に期日または期間を付ける。費用は金額で書く

### 参考資料

- 書くこと：根拠にした資料のリンクまたは資料名と、何の資料かを示す短い説明
- 書かないこと：先方が開けない資料（社内向けのセッションログ、社内資料）
- 粒度の目安：1項目1行

## 文書全体の制約

- 見出しは[README.md](README.md)の「見出しの規約」に従う
- 文書名（`#`）には、提案の対象と先方の名前を入れる。先方の名前には敬称（様）を付ける
- 文体は敬体にそろえる（GRM-001）。先方に渡す文書のため
