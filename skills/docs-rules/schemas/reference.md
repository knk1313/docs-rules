# リファレンス（reference）

書き方の型は[README.md](README.md)を参照。

## 目的と読み手

- 目的：読み手が、作業の最中に必要な事実を引けるように、項目を決まった型で並べる。設定項目の一覧、コマンドの一覧、用語集、人が書く仕様の説明がこの種別に当たる
- 読み手：対象を使っている人。目当ての項目を探して、その項目だけを読む前提で書く
- 対象外：APIの仕様のように、コードからツールで生成する文書。生成するツールが見出しを決めるため、必須セクションの照合が当たらない。作業の手順（ハウツー）と、理由や経緯の説明（解説）もこの種別では書かない
- 位置づけ：Diátaxisのリファレンス（理解×仕事）に当たる（[README.md](README.md)の「文書種別の決め方」）
- 境目：ハウツーは行動の順に並べる。リファレンスは対象の構造か、決まった規則の順に並べ、指示を書かない。理由、経緯、意見は解説に回す

## 入力

- 対象の設定ファイル、コマンドのヘルプ、仕様書、既存の一覧
- セッションログ（[session-log.md](session-log.md)）の`## 決めたこと`のうち、値や名前を決めた項目を入力にできる。決めた理由は写さない

## 必須セクション

リファレンスには、次のセクションを表の順に置く。

| 順 | 見出し名 | 役割 |
| --- | --- | --- |
| 1 | `## 対象` | 何についての参照情報か、どの版や範囲を扱うかを示す |
| 2 | `## 一覧` | 項目を表か箇条書で、決まった型と順で並べる |
| 3 | `## 使用例` | 代表的な使い方を、説明を加えずに示す |
| 4 | `## 関連文書` | 手順や解説の文書へのリンクを並べる |

## セクションごとの書き方

### 対象

- 書くこと：何についての参照情報か、対象の版、扱う範囲と扱わない範囲、項目の並べ方（例：「設定ファイルの記載順」「五十音順」）
- 書かないこと：対象を使う理由、使い方の手順
- 粒度の目安：1〜3文。版は番号で書く

### 一覧

- 書くこと：項目ごとに、名前、意味、取りうる値、既定値などを、すべての項目で同じ型にして並べる。項目が多いときは、`###`で対象の構造に沿って分ける
- 書かないこと：手順、理由、意見、推奨。推奨が要る場合は、ハウツーか解説の文書に分ける
- 粒度の目安：表の場合は1項目1行。各欄は短い語か1文で書く。並べ方は、`## 対象`で示した順とする

### 使用例

- 書くこと：代表的な使い方を、コードブロックか表で示す
- 書かないこと：例の背景や理由の説明、例を使う手順
- 粒度の目安：例は1〜3個。各例に何の例かを示す1文を付ける

### 関連文書

- 書くこと：一覧の項目を使う手順、項目の背景を説明する解説、関連するリファレンスへのリンクと、何の文書かを示す短い説明
- 書かないこと：一覧と関係しない文書
- 粒度の目安：1項目1行。関連する文書がない場合は「関連する文書はない」と一文で書く

## 文書全体の制約

- 見出しは[README.md](README.md)の「見出しの規約」に従う
- 文書名（`#`）には、参照する対象の名前を入れる
- 事実だけを書く。説明、指示、意見を混ぜない（Diátaxis、参照のみ）
- 項目の型と並べ方を、文書の中で変えない。並べ方は、対象の構造（設定ファイルの記載順など）か、五十音順のような決まった規則にする（Red Hat、参照のみ。The Good Docs Project）
