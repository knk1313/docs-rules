# schemas/

文書種別ごとの必須セクションと文書構造を置く。1種別1ファイルで、ファイル名はSKILL.mdの識別名に合わせる（例：`session-log.md`）。表記・文体のルールはここに書かず、[rules/](../rules/README.md)を参照する。

## ファイルの分け方

| ファイル | 種別 | 識別名 |
| --- | --- | --- |
| [session-log.md](session-log.md) | セッションログ | `session-log` |
| [proposal.md](proposal.md) | 提案書 | `proposal` |

## 1種別の書き方

各種別のファイルは、次の`##`見出しをこの順に置く。見出し名は変えない。

1. `## 目的と読み手`：何のための文書か、誰が読むか
2. `## 入力`：何を材料に書くか。ほかの種別を入力にできる場合は、その対応表を置く
3. `## 必須セクション`：必須セクションの表（書式は次の節）
4. `## セクションごとの書き方`：必須セクションごとに、書くこと・書かないこと・粒度の目安
5. `## 文書全体の制約`：見出しの使い方や文体など、文書全体に掛かる制約

## 必須セクション表の書式

必須セクションは、次の書式の表で示す。この表を見出し名の唯一の定義場所とする。`templates/`の見出しは、この表の見出し名をそのまま使う。

```markdown
| 順 | 見出し名 | 役割 |
| --- | --- | --- |
| 1 | `## 概要` | 一言で役割を書く |
```

- 列は「順」「見出し名」「役割」の3つに固定する
- 「見出し名」は、文書に書く見出しの文字列を、先頭の`##`と半角スペースも含めてバッククォートで囲む
- 書式を固定しておき、evaluators/ を実装するとき（Step 2）に見出し名と順序を正規表現で拾えるようにする

## セクションごとの書き方の書式

`## セクションごとの書き方`の下には、必須セクションごとに`###`の見出しを表の順に置き、次の3項目を書く。見出しは表の見出し名から先頭の`##`と半角スペースを除いたものにする。

```markdown
### 概要

- 書くこと：そのセクションに書く内容
- 書かないこと：別のセクションに回す内容と、この文書に書かない内容
- 粒度の目安：文量と具体性の目安
```

- 粒度の目安のうち、文量は「3文以内」「1項目1〜2文」のように数で書く。具体性は「日付と数値を入れる」のように観点で書く
- 粒度の目安は目安であり、守れているかはAIが判定する。機械では判定しない

## 見出しの規約

全種別に共通する見出しの使い方を示す。種別のファイルで上書きする場合は、その種別の`## 文書全体の制約`に書く。

- `#`は文書名に1つだけ使う
- `##`は、必須セクションを表の順にすべて置く。書く内容がないセクションも省かず、その旨を一文で書く
- 任意の`##`見出しは、最後の必須セクションより後ろにだけ足せる。必須セクションの間には挟まない
- `###`以下は、各セクションの中で自由に使える

## 判定の範囲

evaluators/（Step 2）で機械判定するのは次の2点だけとする。

- 必須セクションの見出しがすべてあるか
- 必須セクションの見出しが表の順に並んでいるか（間に別の見出しがあるかどうかではなく、必須セクション同士の相対順序を見る）

セクションの中身と粒度の目安はAIが判定する（`prompts/`）。

## 種別を足す手順

1. SKILL.mdの種別の表に、種別名・識別名・例を足す
2. このディレクトリに`<識別名>.md`を、「1種別の書き方」の型で作る
3. 上の「ファイルの分け方」の表に1行足す
4. `templates/<識別名>.md`を、必須セクション表の見出し名で作る
