# ハウツー（how-to）

書き方の型は[README.md](README.md)を参照。

## 目的と読み手

- 目的：読み手が、すでに決めている目的を果たせるように、作業の手順を順に示す。手順書、作業マニュアル、セットアップの手順、障害が起きたときの対処がこの種別に当たる
- 読み手：何をしたいかを分かっていて、作業の最中に文書を開く人。対象の道具や製品の基本は知っている前提で書く
- 対象外：初めて学ぶ人に一本道をたどらせる入門（チュートリアル）、設定項目の一覧のような事実の参照（リファレンス）、なぜそうなっているかの説明（解説）
- 位置づけ：Diátaxisのハウツー（行動×仕事）に当たる（[README.md](README.md)の「文書種別の決め方」）
- 境目：チュートリアルは学ぶための一本道で、選択肢を扱わない。ハウツーは目的を果たすための手順で、読み手の状況による分岐を扱う。手順に要る事実は表にまとめず、リファレンスへのリンクにする

## 入力

- 作業の記録、コマンドの履歴、画面の操作の記録、既存の手順書
- セッションログ（[session-log.md](session-log.md)）を入力にできる。対応は次の表のとおり

| セッションログのセクション | ハウツーで使うセクション |
| --- | --- |
| `## 概要` | `## 目的` |
| `## 決めたこと` | `## 前提`（手順の前に決まっている条件） |
| `## 次に引き継ぐこと` | `## 手順` |
| `## 参照` | `## 関連文書` |

- セッションログの検討の経緯と理由は、手順に写さない。要る場合は解説の文書に分け、`## 関連文書`からリンクする

## 必須セクション

ハウツーには、次のセクションを表の順に置く。

| 順 | 見出し名 | 役割 |
| --- | --- | --- |
| 1 | `## 目的` | 何を達成するための手順か、どんなときに使うかを示す |
| 2 | `## 前提` | 始める前に要る権限、環境、済ませておく作業を示す |
| 3 | `## 手順` | 番号付きの箇条書で、一つの手順に一つの動作を書く |
| 4 | `## 関連文書` | 関連する手順、解説、リファレンスへのリンクを並べる |

## セクションごとの書き方

### 目的

- 書くこと：手順を終えたときに達成できること、この手順を使う場面。障害の対処では、起きている症状を書く
- 書かないこと：なぜその方法を選んだかの説明（解説の文書に回す）、手順そのもの
- 粒度の目安：1〜3文。達成できることは、読み手が確かめられる状態で書く

### 前提

- 書くこと：要る権限、環境と版、手元に用意するもの、先に済ませておく作業。先に済ませる作業の手順書があれば、そのリンクを付ける
- 書かないこと：環境を一から作る手順（別のハウツーかチュートリアルに回す）
- 粒度の目安：1項目1行の箇条書。版は番号で書く。前提がない場合は「前提はない」と一文で書く

### 手順

- 書くこと：作業の順に、番号付きの箇条書で並べる。一つの手順に一つの動作を書き、動作を表す語で文を終える。読み手の状況で分かれる手順は、「〜の場合は、〜する」の形で書く
- 書かないこと：動作の理由の長い説明（解説の文書へのリンクにする）、手順に関係しない選択肢
- 粒度の目安：1手順1〜2文。入力するコマンドや値は、コードブロックかコードスパンで手順の直下に置く。手順が10を超えるときは、`###`で段階に分ける
- 結果の確認（任意）：手順を終えた後に、うまくいったかを確かめる方法を書く場合は、`## 手順`の最後に`### 結果の確認`を置く。期待する出力や画面の状態を書く

### 関連文書

- 書くこと：前後に行う手順、手順の理由を説明する解説、手順で使う設定値のリファレンスへのリンクと、何の文書かを示す短い説明
- 書かないこと：手順に関係しない文書
- 粒度の目安：1項目1行。関連する文書がない場合は「関連する文書はない」と一文で書く

## 文書全体の制約

- 見出しは[README.md](README.md)の「見出しの規約」に従う
- 文書名（`#`）は「〜する方法」「〜する手順」の形にし、何をする手順かを文書名だけで分かるようにする。名詞だけの文書名にしない（Diátaxis、参照のみ）
- 障害が起きたときの対処も、この種別で書く。文書名は「〜が起きたときの対処」の形にする（Good Docs、Red Hat、GitLabは独立した型にしているが、種別を足さない）
- 一つの文書には、一つの目的の手順だけを書く。目的が二つあるときは、文書を分ける（Diátaxis、参照のみ）
- 手順の中に説明が要る箇所は、本文に書かず、解説の文書へのリンクにする（Diátaxis、参照のみ。The Good Docs Project）
- 手順が1〜2文で終わる文書は作らず、ほかの文書に統合する（GitLab、参照のみ）
