# Markdown記法

見出し、箇条書、コードブロック、リンク、表など、Markdownの記法の単位で守るルールを示す。書き方の型と出典の略称は[README.md](README.md)を参照。

> 出典のCommonMark Specは第0.31.2版（2024年1月28日）の節番号で示す。原文はCC BY-SA 4.0のため写さず、自分の文章で書いている。表はCommonMark Specにはなく（GitHub Flavored Markdownの拡張）、表のルールはmarkdownlintだけを出典にする。
>
> 「判定」のmarkdownlintのルール名はMD番号で書く。各ルールの設定は[evaluators/.markdownlint-cli2.jsonc](../evaluators/.markdownlint-cli2.jsonc)にあり、設定の方針は[evaluators/README.md](../evaluators/README.md)を参照。

## 見出し

### MKD-001 見出しは「#」の形で書き、階層を1段ずつ下げる

- ルール：見出しは行頭の「#」の数で階層を示す形（ATX形式）で書き、下に「===」「---」を引く形（Setext形式）は使わない。階層は1段ずつ下げ、「##」の直下に「####」を置かない
- 理由：「#」の数を見れば階層が分かる。階層を飛ばさなければ、目次と節の対応が崩れない
- 出典：CommonMark Spec 4.2・4.3、markdownlint MD001・MD003
- 判定：機械（markdownlint：MD001、MD003）
- 例：「## 手順」の直下の「#### 準備」→「### 準備」

### MKD-002 文書は見出し1で始め、見出し1は文書に1つだけ置く

- ルール：文書の1行目を「# 題名」にし、見出し1はその1つだけにする。節の見出しは「##」から始める
- 理由：題名が1つに定まり、文書の先頭を見れば何の文書かが分かる
- 出典：CommonMark Spec 4.2、markdownlint MD025・MD041
- 判定：機械（markdownlint：MD025、MD041）
- 例：「# 概要」と「# 手順」が並ぶ→「# 設定手順」の下に「## 概要」「## 手順」

### MKD-003 「#」の後ろにスペースを1つ入れ、見出しの前後は空行にする

- ルール：「#」と見出しの文字の間にスペースを1つだけ入れる。見出しの前後には空行を1行ずつ置く。見出しは行頭から書き、字下げしない
- 理由：「#」の後ろにスペースがない行は見出しとして扱われない。前後に空行がないと、見出しが前後の段落と続いて見える
- 出典：CommonMark Spec 4.2、markdownlint MD018・MD019・MD022・MD023
- 判定：機械（markdownlint：MD018、MD019、MD022、MD023）
- 例：「#手順」→「# 手順」

## 箇条書

### MKD-004 箇条書の記号は「-」にそろえる

- ルール：箇条書の記号は「-」を使い、「*」「+」は使わない。同じ箇条書の中で記号を混ぜない
- 理由：記号が変わると、CommonMarkではそこで別の箇条書が始まる。1つの箇条書として読ませたい項目が2つに分かれる
- 出典：CommonMark Spec 5.2・5.3、markdownlint MD004
- 判定：機械（markdownlint：MD004）
- 例：「* 項目」→「- 項目」

### MKD-005 番号付きの箇条書は1から順に番号を振る

- ルール：番号付きの箇条書は「1.」から始め、項目ごとに1ずつ増やす。すべての項目を「1.」にする書き方は使わない
- 理由：CommonMarkでは最初の項目の番号だけが表示に使われ、途中の番号は無視される。原文の番号を順にしておくと、原文を読む人と表示を見る人で番号が一致する
- 出典：CommonMark Spec 5.2・5.3、markdownlint MD029
- 判定：機械（markdownlint：MD029）
- 例：「1. 準備」「1. 実行」→「1. 準備」「2. 実行」

### MKD-006 箇条書の記号の後ろはスペース1つにし、入れ子の字下げは記号の幅に合わせる

- ルール：記号の後ろのスペースは1つにする。入れ子の項目は、親の記号とスペースを合わせた幅（「-」なら2字、「1.」なら3字）だけ字下げする。同じ階層の項目は字下げをそろえる
- 理由：字下げが記号の幅と合わないと、入れ子ではなく前の項目の続きの段落として扱われ、階層が崩れる
- 出典：CommonMark Spec 5.2、markdownlint MD005・MD007・MD030
- 判定：機械（markdownlint：MD005、MD007、MD030）
- 例：「-  項目」（スペース2つ）→「- 項目」

### MKD-007 箇条書・コードブロック・表の前後は空行にする

- ルール：箇条書、コードブロック、表の前後には空行を1行置く。段落の直後に続けて書かない
- 理由：空行がないと、箇条書が前の段落の続きとして扱われたり、表が表として認識されなかったりする。処理系による差も出る
- 出典：CommonMark Spec 4.5・5.3、markdownlint MD031・MD032・MD058
- 判定：機械（markdownlint：MD031、MD032、MD058）
- 例：「手順は次のとおり」の直後の「- 項目」→「手順は次のとおり」と「- 項目」の間に空行を置く

## コードブロック

### MKD-008 コードブロックは「```」で囲み、言語名を付ける

- ルール：コード、コマンド、ディレクトリ構成は「```」で囲んだブロックに書き、開きの「```」の後ろに言語名（`bash`、`json`、`text`）を付ける。4字下げで示す形と「~~~」の囲みは使わない
- 理由：囲みがあるとブロックの境界がはっきりし、言語名があると表示側で色分けできる。字下げの形は、箇条書の中では入れ子と区別がつかない
- 出典：CommonMark Spec 4.4・4.5、markdownlint MD040・MD046・MD048
- 判定：機械（markdownlint：MD040、MD046、MD048）
- 例：「```」だけで始まるブロック→「```bash」

## 強調とリンク

### MKD-009 強調は「**」で書き、強調を見出しの代わりにしない

- ルール：強調は「**」で囲み、「__」は使わない。斜体は「*」で囲み、「_」は使わない。段落全体を強調して見出しの代わりにしない
- 理由：記号をそろえると、検索や置換で強調の箇所を拾える。強調した段落は見出しとして目次に出ず、階層にも入らない
- 出典：CommonMark Spec 6.2、markdownlint MD036・MD049・MD050
- 判定：機械（markdownlint：MD036、MD049、MD050）
- 例：「`__注意__`」→「`**注意**`」

### MKD-010 リンクは`[文言](URL)`の形で書き、文言はリンク先が分かる語にする

- ルール：URLをそのまま本文に置かず、`[文言](URL)`の形で書く。文言には「こちら」「ここ」「リンク」のような、リンク先を示さない語を使わない。リンク先が空のリンクを置かない
- 理由：URLをそのまま置くと、処理系によってリンクにならないことがある。文言がリンク先を示していれば、文言だけを読んでも行き先が分かる
- 出典：CommonMark Spec 6.3・6.5、markdownlint MD034・MD042・MD059
- 判定：機械（markdownlint：MD034、MD042、MD059、textlint：docs-rules/mkd-010）
- 例：「手順は`[こちら](https://example.com/guide)`」→「手順は`[設定ガイド](https://example.com/guide)`」

> markdownlint：MD059が判定するのは、空の文言と英語の決まり文句（here、link、more）だけである。「こちら」「ここ」「リンク」のような日本語の語は、textlint：docs-rules/mkd-010で判定する（#21）。prh辞書は本文のすべての語に当たり、リンクの文言だけに絞れないため、リンクの文言だけを見る自前のルールにした。

### MKD-011 画像には代替テキストを付ける

- ルール：画像は`![代替テキスト](パス)`の形で書き、代替テキストに画像の内容を書く。空にしない
- 理由：画像が表示されない環境や読み上げでは、代替テキストだけが内容を伝える
- 出典：CommonMark Spec 6.4、markdownlint MD045
- 判定：機械（markdownlint：MD045）
- 例：「`![](flow.png)`」→「`![採点の流れ](flow.png)`」

### MKD-012 HTMLのタグを直接書かない

- ルール：本文にHTMLのタグを書かない。Markdownの記法で書けないものは、書き方を変えるか、コードブロックに入れる。テンプレートの案内に使うコメント（`<!-- -->`）は除く
- 理由：タグは処理系によって表示されたりされなかったりする。Markdownのまま読むときにも邪魔になる
- 出典：CommonMark Spec 4.6・6.6、markdownlint MD033
- 判定：機械（markdownlint：MD033）
- 例：「`前半<br>後半`」→「前半」と「後半」を別の段落にする

## 空白と行

### MKD-013 行末に空白を残さず、空行を2行以上続けず、ファイルの末尾は改行1つで終える

- ルール：行末のスペースを残さない。空行は続けて1行までにする。ファイルの末尾は改行1つで終える。字下げにタブを使わない
- 理由：行末のスペース2つは強制改行の記法になり、見えない記号で表示が変わる。空行の数とファイル末尾がそろっていると、差分に無関係な変更が混ざらない
- 出典：CommonMark Spec 2.1・2.2・4.9・6.7、markdownlint MD009・MD010・MD012・MD047
- 判定：機械（markdownlint：MD009、MD010、MD012、MD047）
- 例：「文の終わり」の後ろのスペース2つ→スペースを消す

## 表

### MKD-014 表の各行は同じ数のセルにし、行の先頭と末尾に「|」を置く

- ルール：表の各行のセルの数を見出し行と同じにする。各行の先頭と末尾に「|」を書く
- 理由：セルの数が違う行は表として崩れる。先頭と末尾の「|」があると、行の範囲が見た目で分かる
- 出典：markdownlint MD055・MD056
- 判定：機械（markdownlint：MD055、MD056）
- 例：「a | b」→「| a | b |」
