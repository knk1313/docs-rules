# 表記

英数字、スペース、記号など、文字の単位で守るルールを示す。書き方の型と出典の略称は[README.md](README.md)を参照。

> 「出典」のJTFスタイルガイドの項目番号は第4.0版の番号である。「判定」のpreset-jtf-styleのルール名は第2.2版の番号のため、同じ項目でも番号が違う。たとえば第4.0版の2.3.1（全角と半角の間のスペース）は、preset-jtf-styleでは`3.1.1.全角文字と半角文字の間`である。

## 文字間のスペース

### NOT-022 全角文字と半角文字の間にスペースを入れない

- ルール：漢字・仮名と、半角の英数字の間にスペースを入れない。欧文を引用するときの、欧文の語と語の間のスペースは残す。インラインのコード（`` `code` ``）とリンク（`[文言](URL)`）の前後は、スペースを入れても入れなくてもよい
- 理由：スペースの有無が書き手ごとに分かれると、同じ語が検索で一致しなくなる。入れないほうに決めておけば、迷わずにそろえられる。インラインのコードとリンクは、前後が詰まると境目が見えにくいため例外にする
- 出典：JTFスタイルガイド 2.3.1
- 判定：機械（textlint：ja-space-between-half-and-full-width、ja-no-space-around-slash）
- 例：「Claude Code の設定を 3 か所変える」→「Claude Codeの設定を3か所変える」

> 「/」の前後のスペースも、ja-no-space-around-slashで判定する。インラインのコードとリンクの前後を判定するja-space-around-codeとja-space-around-linkは、`evaluators/textlintrc.json`で切ってある。

### NOT-023 全角文字どうしの間にスペースを入れない

- ルール：漢字・仮名・全角記号どうしの間にスペースを入れない
- 理由：和文はスペースで語を区切らない。途中にスペースがあると、読み手は文の切れ目かと迷う
- 出典：JTFスタイルガイド 2.3.1
- 判定：機械（textlint：jtf-style/3.1.2.全角文字どうし、ja-no-space-between-full-width、docs-rules/not-023、ja-nakaguro-or-halfwidth-space-between-katakana）
- 例：「設定を 変更する」→「設定を変更する」

> jtf-style/3.1.2.全角文字どうしは、片仮名どうしの間のスペース（「データ ベース」）を複合語の区切りとみなし、指摘しない。漢字や平仮名の間のスペースは、ja-no-space-between-full-widthで判定する。全角スペースと、読点や句点の後のスペースは、docs-rules/not-023で判定する。片仮名の語の間の全角スペースは、ja-nakaguro-or-halfwidth-space-between-katakanaでも判定する。

### NOT-024 括弧の内側と外側にスペースを入れない

- ルール：括弧の前後と、開き括弧の直後・閉じ括弧の直前にスペースを入れない
- 理由：括弧の全角文字には前後の余白が含まれている。スペースを足すと間が空きすぎ、括弧の中と外の結び付きが見えにくくなる
- 出典：JTFスタイルガイド 2.3.3
- 判定：機械（textlint：jtf-style/3.3.かっこ類と隣接する文字の間のスペースの有無、ja-no-space-around-parentheses）
- 例：「設定 （初期値） を使う」→「設定（初期値）を使う」

## 英数字

### NOT-001 半角カナを使わない

- ルール：カタカナは全角で書き、半角カナを使わない
- 理由：環境によって表示が崩れたり、検索で一致しなかったりする
- 出典：JTFスタイルガイド 2.1.5、textlint：no-hankaku-kana
- 判定：機械（textlint：no-hankaku-kana、jtf-style/2.1.5.カタカナ）
- 例：「ｻｰﾊﾞｰ」→「サーバー」

### NOT-015 数字と英字は半角で書き、文書の中でそろえる

- ルール：数字と英字は半角で書く。1桁の数だけ全角にするといった使い分けもしない
- 理由：全角と半角が混ざると、検索や並べ替えで同じ語として扱われず、見た目もそろわない
- 出典：公用文作成の考え方 Ⅰ4エ・Ⅰ6エ、JTFスタイルガイド 2.1.8・2.1.9
- 判定：機械（textlint：jtf-style/2.1.8.算用数字、jtf-style/2.1.9.アルファベット）
- 例：「手順１とＳｔｅｐ 2」→「手順1とStep 2」

## 記号

### NOT-002 句点は「。」、読点は「、」を使う

- ルール：句点には「。」、読点には「、」を使う。「．」「，」を混ぜない
- 理由：句読点がそろっていないと、文の切れ目を見誤りやすく、機械での文の分割もずれる
- 出典：公用文作成の考え方 Ⅰ5(1)ア、JTFスタイルガイド 1.2.1・1.2.2・3.1.1・3.1.2、textlint：ja-no-mixed-period
- 判定：機械（textlint：docs-rules/not-002、ja-no-mixed-period、jtf-style/1.2.1.句点(。)と読点(、)）
- 例：「設定を変更した．動作も確認した．」→「設定を変更した。動作も確認した。」

> docs-rules/not-002は全角の「．」「，」を、jtf-style/1.2.1.句点(。)と読点(、)は和文の中の半角の「.」「,」を判定する。ja-no-mixed-periodは段落の末尾の句点を判定する。
>
> docs-rules/not-002は、数字に挟まれた「．」「，」を小数点と桁区切りとみなし、半角の「.」「,」に直す候補を返す。「1，2，3」のような数字の列挙も同じ候補になるが、列挙のときは「1、2、3」と読点で区切る。

### NOT-003 「！」「？」を使わない

- ルール：文末に「！」「？」を付けない。問いかけは「〜か。」で書く
- 理由：符号に頼ると調子だけが強くなり、内容の確かさが伝わらない
- 出典：公用文作成の考え方 Ⅰ5(2)ア、textlint：no-exclamation-question-mark
- 判定：機械（textlint：no-exclamation-question-mark）
- 例：「期限に間に合いました！」→「期限に間に合った。」

## 見えない文字

### NOT-037 見えない文字と、分解された文字を使わない

- ルール：ゼロ幅スペースや制御文字のように画面に表示されない文字を、本文に残さない。濁点や半濁点を別の文字として分けた形（Unicodeの分解形）の仮名を使わない
- 理由：見えない文字は検索や置換に掛からず、コピーした先で不具合を起こす。分解形の仮名は、見た目が同じでも別の文字列として扱われ、検索で一致しない
- 出典：textlint：no-zero-width-spaces、textlint：no-invalid-control-character、textlint：no-nfd
- 判定：機械（textlint：no-zero-width-spaces、no-invalid-control-character、no-nfd）
- 例：ゼロ幅スペースの入った「設定を変える」→スペースを消した「設定を変える」

> macOSのファイル名から写した文字は、分解形になっていることがある。
