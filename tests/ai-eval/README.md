# tests/ai-eval/

AIで判定するルールについて、AI評価（`skills/docs-rules/prompts/evaluate.md`）の検出率、誤検出、実行ごとの揺れを測る（#77）。

評価にはモデルの呼び出しが要る。APIの従量課金をかけないため、CIでは評価せず、手元のClaude Codeのセッションでサブエージェントに評価させる。CIで動くのは、対の文と結果のファイルの形を確かめるテストと、記録した結果の集計だけである。

## 置くもの

このディレクトリに置くファイルは次のとおり。

| パス | 中身 |
| --- | --- |
| `pairs/<ルールのファイル名>.jsonl` | AIで判定するルールの対の文。形は`tests/corpus/pairs/`と同じ |
| `results/<日付>-<ルールのファイル名>-<モデル>-r<回>.json` | 1回の評価の結果。文書ごとに、指摘したルールIDの一覧を持つ。複数のルールのファイルをまとめて評価したときは、ルールのファイル名を`rest`のようにまとめた名前にする |
| `human-results/<日付>-<モデル>-r<回>.json` | 人が書いた文書（`tests/corpus/human/`）の段落を評価した結果。正解のラベルはないため、指摘したルールIDと該当箇所を残す |
| `prepare.mjs` | 対の文から、評価する文書を書き出す |
| `collect.mjs` | サブエージェントが書いた文書ごとの結果を、1回分の結果のファイルにまとめる |
| `report.mjs` | 結果から、ルールごとの表を出す。モデルは呼ばない |

## 測る数

ルールごとに、次の数を出す。

- 検出率：違反した文で、期待したルールIDが出た割合
- 直した文での誤検出：直した文で、期待したルールIDが出た数
- 揺れた対：同じ対で、回によって検出か誤検出の結果が変わった数
- 直した文でのほかの指摘：直した文で出た、ほかのルールIDの指摘の数。短い文では構成のルール（`CMP-`）が当たりやすいため、誤検出とは分けて数える

## 測る手順

セッションで「AI評価を測って」と頼むと、次の手順で進める。ルールのファイルごとに分けて流してよい。

1. 評価する文書を書き出す：`node tests/ai-eval/prepare.mjs <作業用のディレクトリ>/input <ルールのファイル名>`
2. 文書の一覧を、回ごとに並べ替えて二つほどに分ける。同じ対の二つの文が並ばないようにするためである
3. 分けた一覧ごとにサブエージェントを起動し、`evaluate.md`の手順で評価させる。サブエージェントには次を守らせる
   - `evaluate.md`とルールのファイルを最初に一度だけ読み、文書を1件ずつ独立に評価する
   - 文書ごとに、`evaluate.md`の出力の形のJSONを`<作業用のディレクトリ>/r<回>/<文書の名前>.json`に書く
   - `tests/`を読まない。正解が書いてあるためである。ファイル名に含まれるルールIDも手がかりにしない
4. 回ごとに結果をまとめる：`node tests/ai-eval/collect.mjs <作業用のディレクトリ>/r<回> --model <モデル> --run <回> --rule-file <ルールのファイル名>`
5. 表を出す：`node tests/ai-eval/report.mjs`

- 揺れを見る繰り返しは2回から始め、揺れの大きいルールだけ回数を増やす
- 結果はモデルの版で変わる。比べるときは、同じモデルの結果どうしで比べる。`report.mjs`はモデルごとに表を分けて出す
- 対の文を書いたモデルと評価するモデルが同じだと、判定が甘くなりうる。人が書いた文書でも評価し、指摘の傾向を見る。`node tests/ai-eval/prepare.mjs <作業用のディレクトリ>/input --human 10`で出典ごとに10段落を書き出し、`collect.mjs`に`--rule-file`の代わりに`--human`を付けてまとめる

## これまでの測定

2026年11月の測定は、使用量を抑えるため次の量で行った。

- 禁止語（`forbidden-words`）の5ルール：1ルール5対を、3回評価した。3回目は、評価で読むルールを`prompts/ai-rules.md`に絞った後（#88）の手順である
- それ以外の52ルール：1ルール3対を、1回だけ評価した。揺れは測っていない
- 人が書いた文書：3つの出典から10段落ずつ、1回だけ評価した

結果の表は`node tests/ai-eval/report.mjs`で出る。対の文はほぼすべての違反を見つけたが、対の文は違反をはっきり示すように書いており、書いたモデルと評価したモデルも同じである。実際の文書での検出率は、これより低いとみておく
