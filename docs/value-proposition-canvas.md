# VPC value proposition canvas

## ユーザーが

### 解決したい課題・欲求

- AIが生成する文書のフォーマット・見出し構造・情報の粒度・表記を一定にしたい
- 文書作成のルールをプロンプトごとではなく共通の資産として管理したい
- 生成物がルールに準拠しているか、人が目視せずに判断したい
- 形式だけでなく、網羅性・具体性・信頼性といった内容面の品質も評価したい
- 不合格の文書を評価結果にもとづいて自動で修正したい

### 嬉しい（プラス）と感じること

- 毎回同じ構成・同じ粒度の文書が出てくる
- 良い文書の基準が明文化され、チームや将来の自分と共有できる
- 定期実行で生成物が増えても、確認・修正の負担が増えない
- ルールと評価基準を一度作れば、別の文書種別や別のプロジェクトでも再利用できる

### 困り・悩み（マイナス）と感じること

- Markdownの見出し記法や見出し階層が生成のたびに変わる
- セクションごとの情報量・具体性にばらつきがあり、必須項目の欠落や重複が起きる
- 文体・用語・日付・出典の表記がそろわない
- AIへの指示が各プロンプトに分散し、ルールの更新や再利用が難しい
- 何をもって良い文書とするかが決まっておらず、人の目視以外に品質を判断する手段がない

## 私たちが

### 何を提供するか

- 文書作成ルールをコンテキストとして定義し、生成物を機械的またはAIによって評価・改善する文書品質保証ハーネス
- Claude Codeのスキルとして配布し、Markdownの構文・見出し階層・必須セクションなどのルール、評価・修正に使うプロンプト、コードとAIによる評価処理をひとまとめにする

### 嬉しいと感じてもらえるポイント

- スキルを入れるだけで、文書を書く・直す作業にルールが効く
- ルールは共通ファイルとして一箇所で管理し、更新すればすべての生成に反映される
- 良い文書の基準がルールと評価プロンプトの形で残り、再利用可能な資産になる
- 文書種別はルールとテンプレートを足せば増やせる

### 困り・悩み（マイナス）を取り除くための工夫

- 構文・見出し階層・必須セクション・表記はコードで自動検査し、ばらつきを機械的に止める
- 具体性・網羅性・論理性・根拠の明確さなど、コードで見きれない部分はAIに評価させる
- 不合格の文書は評価結果を渡して書き直させ、基準を満たすまで繰り返す
- 期待する生成例と回帰テストを持ち、ルールを更新しても品質が崩れていないことを確認できる
